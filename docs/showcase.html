01 · Overview

What it does

Every morning, Pre Call Agent reads your calendar, identifies which meetings are with known publisher partners, and assembles a deck-ready brief for each one. Inputs span public news, past-call transcripts (uploaded as .txt by the rep), uploaded campaign performance, and internal account notes. The agent never auto-sends — every brief is a draft until a human approves.

Process flow

01
Gather
  • Calendar → today's calls
  • Match against 139-publisher list
  • Pull news (web search)
  • Read uploaded transcripts
  • Read performance CSV
  • Read account notes
02
Synthesize
  • Cross-reference signals
  • What changed since last touchpoint
  • Performance trend (period vs period)
  • Open commitments & threads from past calls
  • Material news (last 90 days)
03
Recommend
  • Account snapshot
  • Performance read
  • 3–5 talking points
  • Campaign suggestions w/ rationale
  • Risks & threads to close
04
Validate & Ship
  • Rep edits any section
  • Approves a final version
  • Opens HTML deck, downloads A4 PDF, or sends to Slack
  • Emails the brief to themselves via Gmail API (HTML, no truncation)
  • Briefing archived in shared Sheet · paginated history
  • Approved briefs can be edited & re-approved in place, or forked into a new draft

How publisher matching works

  1. Title match — event title contains a publisher name or alias (e.g. "LTS Sync" matches LinkedIn via the "LTS" alias)
  2. Domain match — attendee email domain matches a known publisher domain (e.g. @indeed.com → Indeed)
  3. External inferred — neither, but the event clearly involves an external company → tagged unlisted

The 139 publishers are curated in app/publishers.py, sorted into tiers — 26 P0, 113 P1, 0 P2 (placeholder). Reps can promote/demote any entry.

05 · Setup

What to configure before launch

Required environment variables

Key Required Source
GEMINI_API_KEY Yes aistudio.google.com/apikey
GOOGLE_CALENDAR_ID No (defaults to primary) Use rep's email if domain-wide delegation is enabled
GOOGLE_CREDENTIALS_JSON Yes Google Cloud → service account JSON, on a single line
GOOGLE_SHEET_ID Yes From the Sheet URL: docs.google.com/spreadsheets/d/<THIS>/edit
SLACK_WEBHOOK_URL Optional Slack → Apps → Incoming Webhooks. Without it, app shows a copyable preview.
SLACK_DEFAULT_CHANNEL No Defaults to #supply-partnership-product

One-time setup

  1. Google Cloud project → enable Sheets API, Calendar API, and Gmail API → create service account for Sheets → download JSON
  2. Create the Sheet, share it with the service account email, copy its ID
  3. Configure OAuth consent + client with these scopes: openid, userinfo.email, userinfo.profile, calendar.readonly, and gmail.send (for the 📧 Email button)
  4. Gemini key from aistudio.google.com/apikey (~30 seconds) — enable billing on the Cloud project to lift the daily free-tier cap
  5. Slack webhook if posting to channels (optional)
  6. Playwright + Chromium (optional, for highest-fidelity server-side PDFs locally): playwright install chromium. Without it, the 📄 Download PDF button falls back to the browser's Save-as-PDF dialog automatically.
  7. Curate publishers in app/publishers.py — promote LinkedIn to P0, add Glassdoor, fill missing domains

Daily user flow (employees)

  1. Open the app → sign in with Google (one-time consent for calendar.readonly + gmail.send)
  2. See today's calls auto-loaded, sorted by tier
  3. Click into a call → optionally add notes / upload Mojo CSV(s) / upload up to 3 past-call .txt transcripts → click ⚡ Generate briefing
  4. Wait ~10–15 seconds for synthesis (gather steps run in parallel)
  5. Review & edit any section that needs sharpening
  6. Click ✓ Approve, then ship via 📊 Open deck, 📄 Download PDF, 💬 Send to Slack, or 📧 Email (server-side Gmail send to your inbox)
  7. Need to revise a previously-approved brief? Open it from Past briefings → click ✏️ Edit this briefing → make changes → ✓ Re-approve (same record updated). Or 📝 Save as new draft to fork.
  8. Walk into the call
